# myapp.catalog — интернет-магазин на 1С-Битрикс для больших каталогов

**myapp.catalog** — готовый модуль витрины и торговой логики, который заменяет типичную связку «компоненты + шаблоны» на единую архитектуру с быстрым каталогом, поиском и фильтрами. Если в планах **сотни тысяч товаров и торговых предложений**, стандартные решения Битрикса часто упираются в тяжёлые выборки по свойствам и поиск по `LIKE` по всей базе. Этот модуль изначально рассчитан на такой масштаб: данные остаются в вашем инфоблоке и каталоге Битрикса, а **листинг, поиск и фильтрация** работают через **собственные индексы в MySQL** и лёгкий фронт.

## Что умеет модуль

- **Каталог** — разделы, карточки товаров, SKU (торговые предложения), списки с пагинацией и сортировкой.
- **Фильтр** — настраиваемые свойства, цена, артикул; для больших выборок — **денормализованный индекс фильтра** (отдельные служебные таблицы, полная и инкрементальная пересборка, контроль актуальности в админке).
- **Поиск** — отдельный **поисковый индекс** (лексемы и триграммы, веса по названию и свойствам, очередь обновлений); поиск по подстроке и словам **без** обхода всей таблицы товаров.
- **Корзина и оформление заказа** — API для фронта, интеграция с корзиной и заказами Битрикса.
- **Личный кабинет** — заказы, профиль, типовые сценарии авторизации.
- **Главная и контент** — слайдер, блоки, текстовые страницы из инфоблоков (управление контентом без правки шаблонов).
- **ЧПУ и маршрутизация** — свои URL через роутинг D7, единый каркас страниц и REST API для интерактивных блоков.

## Стек реализации

- **1С-Битрикс** — инфоблоки, торговый каталог, цены, заказы, пользователи (привычная админка и обмены).
- **PHP, Bitrix D7** — сервисы, ORM, контроллеры, кеширование, фоновые задачи переиндексации.
- **Vue 3 (ES modules)** — корзина, фильтр, поиск, шапка и др. без тяжёлой SPA на весь сайт; критичные страницы отдаются с сервера для SEO.
- **MySQL** — основные данные Битрикса плюс служебные таблицы **индекса поиска** и **индекса фильтра**, оптимизированные под выборку ID товаров и ранжирование.

## Почему это уместно при 100 000+ позиций

На больших каталогах узкое место — не «нарисовать витрину», а **быстро отфильтровать, найти и открыть нужную страницу списка**. Компонентная модель с множественными join по свойствам и неиндексированным поиском на каждый запрос быстро становится дорогой в поддержке и железе. **myapp.catalog** переносит тяжёлую работу в **подготовленные индексы**: фильтр отдаёт списки по заранее собранным значениям свойств и цен; поиск работает по словарю лексем и триграммам. Изменения в каталоге попадают в индексы через **очередь и задания** — витрина остаётся отзывчивой, а вы не платите полной ценой за каждый клик по чекбоксу фильтра.

Итог для заказчика: **знакомая экосистема Битрикса** (товары, цены, заказы) + **витрина уровня крупного маркетплейса** по скорости каталога, поиска и фильтра — без отдельного «второго сайта» и без внешнего Elasticsearch, если достаточно продуманной схемы на MySQL.
